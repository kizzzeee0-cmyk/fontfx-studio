# FontFX Studio v1.0 — 상세 개발 계획서 및 구현 명세

## 1. 제품 목표

FontFX Studio의 목적은 “포토샵에서 글자를 꾸미는 과정” 중 사용 빈도가 높은 글자별 배치, 다중 획, 내부 그림자, 혼합 모드, 팔레트 조합, 투명 PNG 출력을 한 화면에서 훨씬 빠르게 처리하는 것입니다.

핵심 사용 흐름은 다음과 같습니다.

1. 출력 캔버스 픽셀 크기 결정
2. 시스템/웹/로컬 폰트 선택
3. 단어 입력
4. 한 글자씩 자동 레이어 분리
5. 캔버스에서 직접 위치·크기·회전 조정
6. 필요한 글자들을 그룹화
7. 여러 개의 획과 내부 그림자 적용
8. 색상 추천 또는 팔레트 사용
9. 레이어 순서 미세 조정
10. 전체 PNG 또는 개별 글자 PNG ZIP 출력

## 2. v1.0 제품 원칙

### 원칙 A — 글자 하나가 독립 오브젝트

문자열 전체를 하나의 Canvas text로 처리하지 않습니다. Unicode grapheme 단위로 분리해 각 글자가 독립적인 모델을 가집니다.

각 글자 데이터:

```text
id
text
fontFamily
fontSize
fontWeight
fill
x / y
scale
angle
visible
locked
groupId
strokes[]
innerShadows[]
```

이 구조 덕분에 5글자 단어라도 5개 글자의 위치/크기/각도를 완전히 별도로 수정할 수 있습니다.

### 원칙 B — 숫자 바보다 캔버스 직접 조작 우선

X/Y/각도/배율 숫자 필드는 정밀 보정용입니다. 기본 편집은 중앙 캔버스에서 직접 수행합니다.

- 본체 드래그 → 위치
- 네 모서리 핸들 → 균일 크기
- 상단 회전 핸들 → 각도
- Shift+클릭 → 다중 선택

### 원칙 C — 효과 개수 제한 없음

`strokes`와 `innerShadows`는 고정 슬롯이 아니라 배열입니다. + 버튼이 새 객체를 배열에 추가하므로 UI가 감당 가능한 범위 내에서 계속 추가할 수 있습니다.

### 원칙 D — 화면 캡처가 아닌 재렌더링 출력

최종 PNG는 미리보기 캔버스의 화면 픽셀을 복사하지 않습니다. 출력 전용 Canvas에 현재 프로젝트 데이터를 다시 그립니다. 따라서 편집 창의 표시 배율과 최종 이미지 해상도가 분리됩니다.

## 4. 폰트 시스템

### 4.1 시스템 폰트

브라우저가 운영체제에서 찾을 수 있는 폰트 이름을 CSS font-family로 지정합니다.

### 4.2 CSS 웹폰트

사용자가 CSS URL과 정확한 family 이름을 입력하면 `<link rel="stylesheet">`를 동적으로 추가합니다. `document.fonts.load()`를 통해 사용 가능 여부를 기다립니다.

### 4.3 직접 폰트 URL

FontFace API를 사용합니다.

```text
new FontFace(customName, url(fontFileUrl))
→ load()
→ document.fonts.add()
```

### 4.4 로컬 폰트

File API로 ArrayBuffer를 읽고 FontFace에 직접 전달합니다. 외부 업로드가 필요하지 않습니다.

## 5. 문자 분해

가능한 브라우저에서는 `Intl.Segmenter(granularity: grapheme)`를 사용합니다.

장점:

- 한글 완성형 글자
- 조합 문자
- 일부 이모지/결합 문자의 비정상 분리 방지

지원하지 않는 환경에서는 `Array.from()`으로 폴백합니다.

## 6. 직접 조작 엔진

외부 그래픽 라이브러리를 사용하지 않고 다음을 자체 구현했습니다.

### 6.1 히트 테스트

1. 포인터의 월드 좌표를 얻음
2. 각 글자의 역회전 행렬을 적용
3. 글자 로컬 좌표로 변환
4. 회전 전 로컬 경계 사각형 안인지 검사

### 6.2 이동

포인터 다운 시 선택된 모든 글자의 원래 좌표를 저장하고, 포인터 이동량 Δx/Δy를 더합니다.

### 6.3 크기

활성 글자 중심에서 포인터까지의 거리 비율을 사용해 균일 scale을 구합니다.

### 6.4 회전

글자 중심 → 포인터 벡터의 `atan2` 각도 차를 사용합니다. Shift를 누르면 15° 단위로 스냅합니다.

## 7. 레이어 시스템

`state.chars` 배열의 앞이 하단, 뒤가 상단입니다.

- 맨 위 → 배열 마지막
- 맨 아래 → 배열 첫 번째
- 위/아래 한 단계 이동
- 드래그 앤 드롭 재배열

각 레이어는 visible / locked 속성을 가집니다.

## 8. 그룹 설계

그룹은 무거운 중첩 오브젝트가 아니라 `groupId` 기반 논리 그룹입니다.

이 설계를 선택한 이유:

- 그룹 후에도 글자별 좌표를 잃지 않음
- 그룹 해제가 단순함
- 개별 PNG 출력이 쉬움
- 효과만 함께 수정하는 사용자의 핵심 요구에 적합

그룹화 시 활성 글자의 효과 스택을 그룹 구성원에게 동기화합니다. 이후 `그룹 효과 동시 편집`이 켜져 있으면 동일 effect id를 기준으로 구성원 전체의 값을 함께 변경합니다.

## 9. 다중 획 렌더링

획 데이터 구조:

```text
id
enabled
width
position: outside | center | inside
blend
opacity
color
```

### 외부 획

Canvas의 strokeText를 두 배 lineWidth로 그린 후 본문 fill을 다시 덮어 내부 절반을 숨깁니다. 이 방식으로 외부 방향에 가까운 결과를 만듭니다.

### 중앙 획

fill 이후 strokeText를 지정 굵기로 중첩합니다.

### 내부 획

별도 레이어에 strokeText를 만든 후 글자 알파 마스크로 destination-in 합성하여 글자 내부만 남깁니다.

### 다중 획 순서

효과 배열을 독립 레이어처럼 다루며 ↑/↓로 순서를 바꿀 수 있습니다.

## 10. 내부 그림자 렌더링

내부 그림자는 Canvas 기본 shadow 속성 하나만으로는 Photoshop식 다중 제어가 어렵기 때문에 글자 마스크 기반으로 계산합니다.

1. 글자 흰색 알파 마스크 생성
2. angle + distance로 마스크 이동
3. size 값으로 이동 마스크 blur
4. 원본 마스크와 이동/blur 마스크의 알파 차이를 구함
5. 글자 내부 영역으로 제한
6. choke로 경계를 조임
7. contour 함수로 감쇠 곡선을 변환
8. color + opacity로 그림자 레이어 생성
9. blend mode로 원문 위에 합성

내부 그림자 데이터:

```text
blend
color
opacity
angle
distance
choke
size
contour
quality
```

## 12. 색상 추천 알고리즘

기준 HEX를 RGB → HSL로 변환한 뒤 다음 조합을 생성합니다.

- 동일 Hue의 파스텔 L 보정
- ±30° 인접색
- +180° 보색
- +150° 분할 보색 인접 후보
- 동일 Hue의 진한 외곽선 후보
- 채도 낮은 매우 밝은 중성 후보

이 방식은 온라인 API가 없어도 즉시 작동합니다.

## 13. 팔레트

v1.0은 방송 프로필, 로고, 귀여운 타이포그래피에 바로 쓰기 쉬운 연한 계열 위주 16개 팔레트를 내장합니다.

향후에는 팔레트 즐겨찾기/사용자 저장/최근 사용 색상을 확장할 수 있습니다.

## 14. 출력 시스템

### 14.1 전체 PNG

출력 캔버스 크기:

```text
project.width × exportScale
project.height × exportScale
```

배경을 채우지 않으므로 alpha 0의 완전 투명 배경입니다.

### 14.2 개별 글자 — Tight

글자 효과 표면의 크기와 회전 후 axis-aligned bounding box를 계산해 최소 투명 여백만 남깁니다.

### 14.3 개별 글자 — Canvas Position

원본 캔버스 크기를 유지하고 해당 한 글자만 동일 좌표에 렌더합니다.

## 15. ZIP 시스템

외부 JSZip 의존성을 제거하기 위해 ZIP STORE 포맷을 직접 구현합니다.

포함 요소:

- CRC32 계산
- Local File Header
- Central Directory Header
- UTF-8 filename flag
- End of Central Directory

PNG 파일은 이미 압축된 포맷이므로 ZIP 내부에서 다시 Deflate 하지 않고 STORE 방식으로 넣어도 실용적입니다.

## 16. 화질 정책

- 미리보기는 작업 창 크기에 맞춘 zoom으로 표시
- 출력은 별도 캔버스에서 원본 좌표로 다시 렌더
- 글자 효과 표면은 캐시된 고배율 오프스크린 Canvas 사용
- 출력 배율 1×/2×/4×
- PNG 무손실

## 17. Undo / Redo

프로젝트 핵심 상태를 JSON snapshot으로 기록합니다.

- 최대 80단계
- Ctrl+Z
- Ctrl+Y
- UI 버튼
- 숫자 입력/색 변경은 짧은 debounce 후 기록
- 드래그/회전/크기 변경은 pointerup 시 한 단계로 기록

## 18. 프로젝트 저장 형식

`.fontfx.json`

보존:

- 캔버스 크기
- 모든 글자 데이터
- 위치/각도/배율
- 글자별 폰트 이름
- 채우기
- 획 배열
- 내부 그림자 배열
- 그룹 정보
- 웹 CSS/URL 폰트 메타데이터

보존하지 않음:

- 사용자가 로컬에서 올린 폰트 파일의 바이너리

로컬 폰트를 JSON에 base64로 포함하면 프로젝트 파일이 지나치게 커지고 폰트 라이선스 이슈도 생길 수 있어 v1.0에서는 제외합니다.

## v1.2 Gradient Fill

- 각 글자는 `fillMode: solid | linear | radial`을 가집니다.
- `gradient`에는 `angle`, `range`, `centerX`, `centerY`, `stops[]`를 저장합니다.
- `stops[]`는 `{id, position, color}` 구조이며 고정 개수 제한이 없습니다.
- 선형 그라데이션은 글자 로컬 좌표에서 중심과 범위를 기준으로 시작점/끝점을 계산합니다.
- 원형 그라데이션은 동일한 중심 좌표와 범위를 반경으로 변환합니다.
- 최종 PNG 재렌더링에서도 동일한 gradient 데이터를 사용하여 미리보기와 출력 차이를 줄입니다.
